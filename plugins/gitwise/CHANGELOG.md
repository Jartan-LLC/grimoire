# Changelog

## 1.5.0

- `github-conventions` covers stacked pull requests (`stacks.md`). When a change builds on an open PR's unmerged work, your agent branches from that PR's branch once that PR has finished review, or earlier when waiting would stall the work, telling you that each change to it then means a restack. It bases the new PR on that branch and links the two into a stack with `gh api`, and tells you before branching when that PR sits below its stack's top, where GitHub cannot add a PR. It roots a stack on the branch the stack merges into, and never stacks a sub-issue branch on its parent feature branch's PR; sub-issues that build on each other may stack within the parent branch.
- Your agent merges a stack bottom up with your project's merge method, through `gh stack merge` where installed or GitHub's asynchronous merge endpoint, since `gh pr merge` refuses a stacked PR; a person can use the web UI. After a partial merge it checks that the next PR holds only its own commits.
- Before pushing to a PR, your agent checks for PRs based on its branch. When a PR in a stack changes under branches above it, or the next PR still carries a merged PR's commits, your agent rebases those branches and pushes them with `--force-with-lease`, with the approval your project requires for a force-push, or yours where it states none. This is the one exception to never rewriting a pushed commit.

## 1.4.1

- `github-conventions`' review format no longer opens with a count of the files reviewed.

## 1.4.0

- `github-conventions` tells your agent to open a PR as a draft and to mark it ready (`gh pr ready`) when it is ready for someone else to review or merge. Your agent does not always mark a draft PR ready: some models often leave it a draft when you say the work is done without asking for the PR to be marked ready. If it leaves the PR a draft, run `gh pr ready` yourself.

## 1.3.0

- `github-conventions` has rules for issue bodies (`issue-format.md`): your agent writes for whoever implements the issue, states the problem before any fix, keeps where the problem shows, the expected result, the scope and the constraints, and leaves out the files to touch, the steps of a fix, effort estimates and the story of the session, and titles it with the component, then the symptom or the need.
- `github-conventions` describes implementation plans as saved in `.claude/workspace/`, not posted on the issue, and a plan you have your agent post leaves out Patterns & Conventions Found, Files to Create/Modify and the Implementation Checklist, which are working notes.
- `commit-pr-writing` assumes GitHub's default squash merge, where every commit message on the branch lands and the PR description does not, and no longer looks up your repository's merge setting. If you merge another way, state it in your agent instruction file or CONTRIBUTING.md and your agent follows it; where your PR description lands, your agent writes it as a commit message and leaves out where to start reading.
- `commit-pr-writing` no longer counts the PR description's opening what-and-why, or a flag with its reason, as retelling the commit messages.
- The PR description states each decision a reviewer might question, a change they would propose that was rejected included, with its reason, and no longer has "Changed in review" and "Declined from review" lines that say what review prompted.
- `github-conventions`' review format no longer assumes the review is posted on the PR, or asks for inline comments.
- In a public repository, your agent keeps exploit and reproduction detail of a security flaw whose fix is not released out of issues, PR titles and descriptions, and every commit message but the fixing one, unless the text links the released fix or a public advisory.
- The PR description no longer ends with "merging is all"; it ends with a step for the merger or contributors only when there is one.

## 1.2.0

- The review comment format in `github-conventions` no longer ends with a "Generated by Claude" footer.
- Your agent follows your project's commit convention, and Conventional Commits only
  where none is stated. It marks a change as breaking only when it breaks something
  for your users.
- New `commit-pr-writing` skill: what a commit message, a PR title and a PR description say, and which of them lands on your default branch under your repository's merge setting.
- `github-conventions`: a fix to a commit not yet pushed is folded into that commit, and a pushed commit is never rewritten.
- A second hook prompts the model to load `commit-pr-writing` on `git commit`, `git push`, `gh pr create` and `gh pr edit`. The existing hook now only names `github-conventions`, which already holds the numbered-list and commit-convention rules it used to repeat.
